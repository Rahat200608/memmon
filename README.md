# memmon

Универсальный монитор памяти и CPU для любой Python-программы: Telegram-бот, сайт, скрипт, сервис.
Подключается одной строкой (или вообще без правки кода) и пишет в CSV-файл, как программа расходует ресурсы со временем.

Название: **mem**ory **mon**itor. Его можно сменить на любое другое (см. раздел «Переименование»).

## Зачем это нужно

- Найти утечку памяти: видно, растёт ли потребление непрерывно или стабилизируется.
- Выбрать хостинг: пиковое значение RAM показывает, какой минимальный тариф потребуется.
- Оценить влияние клиентов: колонка `connections` показывает число соединений в каждый момент, а время в логе можно сопоставить с отчётом нагрузочного теста.
- Измерить чужой проект без правки его кода: `python -m memmon script.py`.

## Требования

- Python 3.8 или новее
- Библиотека `psutil` (ставится автоматически)
- Работает на Windows, Linux и macOS

## Способы использования

Команды из этой таблицы пишутся в разных местах: строки Python идут в файл `.py`, остальное в терминал.

| Что нужно | Где писать | Что писать |
|---|---|---|
| Запустить чужую программу под замером, не трогая её код | терминал | `python -m memmon main.py` |
| Включить монитор из кода одной строкой | начало `.py` файла | `import memmon.auto` |
| Включить с настройками | `.py` файл | `import memmon` и `memmon.start(interval=5)` |
| Нарисовать график по готовому отчёту | терминал | `python -m memmon plot memmon_12345.csv` |

`import memmon.auto` ставь первой строкой программы, чтобы замер шёл с самого старта.

## Что делает каждый файл

```
memmon/
├── pyproject.toml
├── README.md
└── memmon/
    ├── __init__.py
    ├── __main__.py
    ├── auto.py
    └── plot.py
```

| Файл | Назначение |
|---|---|
| `pyproject.toml` | Описание пакета для pip: название, версия, зависимость от `psutil`. Благодаря ему работает `pip install`. |
| `memmon/__init__.py` | Основная логика. Функция `start()` запускает фоновый поток, который раз в заданный интервал замеряет память, CPU, потоки и соединения и дописывает строку в CSV. Повторный вызов `start()` ничего не делает. |
| `memmon/auto.py` | Сокращение. При `import memmon.auto` Python выполняет файл, и монитор запускается сам с настройками по умолчанию. |
| `memmon/plot.py` | Рисует график по CSV-отчёту: память, процессор, потоки и соединения по времени, с отметкой пика. Нужен `matplotlib`. |
| `memmon/__main__.py` | Позволяет запускать чужой скрипт через `python -m memmon script.py [аргументы]`. Запускает монитор, затем выполняет указанный скрипт как обычно. |

## Что пишется в отчёт

Файл `memmon_<имя_скрипта>_<PID>.csv` (например, `memmon_main_8044.csv`) создаётся рядом с программой. PID это номер процесса в системе: у каждого запуска он свой, поэтому отчёты разных запусков не перезаписывают друг друга. Разделитель `;`, открывается в Excel (русские заголовки отображаются корректно).

| Колонка | Смысл |
|---|---|
| `время` | Время замера |
| `память_МБ` | Занятая память (RSS) в МБ, включая дочерние процессы |
| `процессор_%` | Загрузка процессором, % от одного ядра (на нескольких ядрах может быть больше 100) |
| `потоки` | Число потоков программы. Стабильное число означает, что потоки не накапливаются |
| `соединения` | Число открытых сетевых соединений (сокетов). Это не порты, а количество подключений программы, например к серверам Telegram или к клиентам сайта. `-1` значит, что системе не хватило прав его получить |

Сразу под заголовком идёт строка `# процесс: ...`: имя скрипта, PID и **настройки, с которыми монитор реально запущен** (интервал, трассировка, учёт дочерних процессов). Если результат не похож на то, что ты задавал, смотри сначала на неё.

Пиковую память отдельной колонкой не пишу: если память только растёт, она совпала бы с `память_МБ`. Пик указан в итоговой строке, а ещё его можно взять как максимум колонки `память_МБ`.

При штатном завершении программы в конец файла добавляется строка `# ИТОГ`: первый замер, пик, последний замер, средний рост в МБ/мин и время работы. Рост считается между первым и последним замером и не выводится, если замер короче минуты.
Каждая строка пишется сразу, поэтому при аварийном завершении (например, `Killed` из-за нехватки памяти) отчёт сохраняется до последнего замера, только итоговой строки не будет.

## График

Из готового отчёта получается картинка (PNG) с четырьмя линиями: память, процессор, потоки, соединения. Пик памяти отмечен стрелкой, сверху выводится строка `# ИТОГ`.

```
python -m memmon plot memmon_12345.csv
```

Файл `memmon_12345.png` появится рядом с отчётом. Своё имя картинки можно указать вторым аргументом: `python -m memmon plot memmon_12345.csv итог.png`.

Нужен `matplotlib` (`python -m pip install matplotlib`). Если он не установлен, команда подскажет, что сделать. Строки отчёта, которые не удалось прочитать, пропускаются, а переход через полночь учитывается.

## Настройки

Параметры `start()` или переменные окружения:

| Параметр | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| `interval` | `MEMMON_INTERVAL` | `10` | Интервал замера **в секундах** |
| `path` | `MEMMON_FILE` | `memmon_<имя_скрипта>_<PID>.csv` | Куда писать отчёт |
| `children` | нет | `True` | Учитывать память дочерних процессов |
| `trace` | `MEMMON_TRACE=1` | выкл. | Подробная трассировка через `tracemalloc` |

Пример установки переменной в PowerShell:

```
$env:MEMMON_INTERVAL = "5"
python -m memmon main.py
```

В Linux и macOS: `MEMMON_INTERVAL=5 python -m memmon main.py`.

Рекомендации по интервалу: 2-5 секунд для коротких нагрузочных тестов, 60-300 секунд для долгой работы.

## Режим трассировки (MEMMON_TRACE=1)

Показывает, в каких строках кода накапливается память. Включение: `MEMMON_TRACE=1` или `memmon.start(trace=True)`. Для него лучше брать интервал побольше (60-120 секунд).

Результат пишется **не в таблицу CSV**, а в отдельный файл рядом: `<имя отчёта>.csv.trace.txt`. В нём:

1. Каждый интервал до пяти строк вида `файл.py:строка: +X КБ всего, +N объектов`. Это **рост с самого начала замера**, а не за последний интервал. Если одно и то же место растёт из замера в замер, это кандидат на утечку.
2. В конце файла блок `ИТОГ ТРАССИРОВКИ`: топ-3 места с цепочкой вызовов. Читать цепочку нужно снизу вверх: нижняя строка это то место, где память выделена, строки выше это те, кто её вызвал.

Скрыты места, которые относятся к самой трассировке (`memmon`, `tracemalloc`, `linecache`), и мелочи меньше 10 КБ. Первый замер служит точкой отсчёта, поэтому записи начинаются со второго интервала.

Трассировка замедляет программу и сама занимает память, поэтому **цифры RAM и процессора в этом режиме завышены**: на тестах рост памяти получался в несколько раз больше, чем без неё. Для выбора хостинга замеряй без `MEMMON_TRACE`, а трассировку включай только когда ищешь, где именно растёт память.

## Частая ошибка: два вызова запуска

Монитор запускается один раз за процесс. Если в программе стоит и `import memmon.auto`, и `memmon.start(interval=120, trace=True)`, работает тот вызов, что был первым (обычно `auto` с настройками по умолчанию), а второй игнорируется. В этом случае `memmon` пишет предупреждение в консоль, а строка `# процесс:` в отчёте покажет реальные настройки. Оставь что-то одно: либо `import memmon.auto`, либо свой `memmon.start(...)`.

## Почему из одной программы получилось два отчёта

Отчёт создаёт каждый процесс, в котором запущен монитор. Два файла от одного запуска означают два процесса: например, программа перезапустилась (`run.py` запустил `main.py` заново), либо монитор подключён в двух местах. Определить можно по времени: если замеры второго файла начались после конца первого (есть строка `# ИТОГ`), это перезапуск.
Числа из двух файлов не складывай: родительский процесс при `children=True` уже включает память дочерних.

## Как оценить нужный объём RAM для хостинга

1. Запусти программу под монитором без `MEMMON_TRACE` и под реалистичной нагрузкой.
2. Возьми максимум колонки `память_МБ` (или значение «пик» в итоговой строке).
3. Добавь запас 30-50%: хостинг убивает процесс по пику, а не по среднему.

Для проверки сайта под нагрузкой используй отдельный инструмент (например, `locust`). `memmon` фиксирует реакцию программы, но нагрузку не создаёт.

## Ограничения

- Только Python-программы.
- Монитор работает, пока жива программа (поток фоновый и завершается вместе с ней). Чтобы отключить, уберите импорт или запускайте без `python -m memmon`.
- Если у проекта несколько процессов (например, воркеры gunicorn), импортируйте `memmon` в каждом: файлы создаются отдельно на каждый PID, суммировать их нужно самостоятельно.
- Подсчёт соединений на macOS и в некоторых системах может требовать повышенных прав, тогда в колонке будет `-1`.
- Базовая работа проверена на Linux (установка и запись замеров). На Windows и macOS проверь на своём примере.

## Переименование

Чтобы сменить название, замени его в трёх местах:

1. Имя внутренней папки с кодом (`memmon/memmon/`): от него зависит команда `import`.
2. Строка `name = "memmon"` в `pyproject.toml`.
3. Все `import memmon` в `auto.py` и `__main__.py`, а также команду `python -m memmon`.
